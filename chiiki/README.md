# 地域おこし協力隊　地域要件確認ツール

応募者の現住所から、**雲南市への転入が特別交付税措置の対象になるか**を判定し、
出典を明記した根拠テキストを出します。決裁に添える参考資料として使えます。

既存の確認ツールの多くは市町村単位で止まっており、**一部条件不利地域にお住まいの方**
（同じ市町村内でも住所によって結論が変わる）の判定ができません。そこを埋めるためのツールです。

> ### いまはデータが入っていません
>
> 画面・判定エンジン・根拠テキストはできていますが、**データがまだ投入されていません。**
> 原典資料を `data/source/` に置いて取り込むと、判定できるようになります。
> 置き方は [`data/source/README.md`](data/source/README.md) をご覧ください。
>
> データが入るまで、配布物の `地域要件確認ツール.html` は作られません。

---

## 使い方

データを投入してビルドすると、リポジトリ直下に `地域要件確認ツール.html` ができます。
**このファイルを開くだけです。** これ1つで動きます。

- ダブルクリックで開く（インストール不要・インターネット接続も不要）
- 庁内共有フォルダに置いても、URLで開いてもかまいません

入力した内容は、**すべてご自分のパソコンの中だけで処理されます。**
外部のサーバーには一切送信されません。

### 画面の見かた

| | |
|---|---|
| 左 | 入力。都道府県 → 市町村 → 大字 の順に選びます |
| 右 | 判定結果と根拠テキスト。選ぶそばから変わります |

大字が30件を超える市町村では、絞り込み欄が出ます（全国では最大3,753件の市町村があります）。

### 判定の順序

```
① 住所を選ぶ
② 市町村の区分を見る
     全部条件不利地域(a)              → 対象外
     都市地域                          → 対象
     指定都市（条件不利地域を含まない）→ 対象
     一部条件不利地域                  → ③へ
     指定都市（条件不利地域を含む）    → ③へ
③ 大字の区域を見る
     条件不利区域(b)     → 対象外
     (b)以外＝(c)        → 対象（ただし下記「(c) と言い切れる条件」）
     突合できなかった    → 要確認
```

②で結論が出る市町村では、**大字の欄は選べないままになります。**
選ぶ必要がないことが画面でわかるようにしてあります。

### (c) と言い切れる条件

条件不利区域(b) は「過疎みなし区域・振興山村・離島振興対策実施地域・半島振興対策実施地域」の
和集合です。ここに非対称があります。

- **(b) だと言うには**、4法令のうち1つに載っていれば足ります
- **(c) だと言うには**、4法令のどれにも載っていないことを確かめる必要があります

そのため、**区域一覧が1つでも投入されていない法令があると、(c) の判定はできません。**
そういう市町村では、(b) に当たらないことまでは示したうえで「要確認」と表示し、
どの法令の一覧が足りないかを画面と根拠テキストに出します。

投入済みの法令は `data/d1_municipalities.json` の `照合済み法令` に入っており、
一覧を足して取り込み直せば、プログラムを触らずに (c) が出るようになります。

### 例外ルート

次のいずれかに当てはまる方は、住所にかかわらず対象です。
チェックを入れると住所欄が灰色になり、例外ルートで結論を出します。

- 地域おこし協力隊の経験者（同一地域で2年以上活動し、解嘱から1年以内）
- 海外に在留し、市町村の住民基本台帳に登録されていない
- JETプログラムの終了者（2年以上参加し、終了から1年以内）

### 履歴

**「履歴に残す」を押したときだけ**保存されます。押さなければ、入力した住所は
このパソコンに残りません。保存した履歴はブラウザの中だけにあり、外部には送信されません。

共有の端末をお使いの場合は、使い終わったら履歴画面の**「すべて削除」**を押してください。

### 根拠テキストの出しかた

| | |
|---|---|
| コピー | クリップボードに入れて、決裁文書に貼り付けます |
| 印刷 | 根拠テキストだけを1枚に印刷します。ブラウザのPDF出力でそのまま添付できます |
| .txt で保存 | テキストファイルとして保存します |

> 他のページに埋め込んで表示している場合（レビュー用の共有ページなど）は、
> ブラウザの決まりで **ファイルの保存だけが止められます**。
> コピーと印刷はそのまま使えます。

## この判定の限界

1. **番地レベルの指定には対応していません。** 区域指定が旧市町村単位であることを前提にしています。
2. **データの鮮度。** 総務省の資料が更新されたら差し替えが必要です。基準日から3年が過ぎると画面に警告が出ます。
3. **新旧の突合に失敗した大字は「要確認」になります。** 割合は
   `node chiiki/tools/ingest/report-coverage.js` で確かめられます。

本ツールは参考資料を作る補助ツールです。判定の最終責任は使用者にあります。
疑義がある場合は総務省又は島根県へ照会してください。

## 開発者向け

### ファイル構成

```

chiiki/

  data/
    meta.json               基準日・出典・データ状態
    d1_municipalities.json  市町村マスタ      ┐ 取り込みツールが生成
    d2_oaza.json            大字→区域(b/c)    ┘ 手で書かないでください
    d3_principles.json      確認表（区分→記号→原則）

  tools/
    build.js          1つのHTMLにまとめる
    check-data.js     データの整合性検査
    test-judge.js     判定エンジンの単体テスト（架空データ）
    test-ingest.js    新旧突合の単体テスト（合成データ）
    test-pipeline.js  取り込みの通しテスト（合成データ）
    fixtures/         テスト用の架空データ
    ingest/
      read-isj.js        位置参照情報CSVを読む（Shift_JIS対応）
      match-oaza.js      新旧の代表点を突き合わせ、旧市町村を当てる
      build-data.js      中間CSV → d1/d2 JSON
      report-coverage.js 収録率・要確認率・法令の網羅状況
```

### 検査とビルド

```
node chiiki/tools/test-judge.js      # 判定エンジンの全分岐
node chiiki/tools/test-ingest.js     # 新旧突合（原典なしで流せます）
node chiiki/tools/test-pipeline.js   # 取り込みの通し（原典なしで流せます）
node chiiki/tools/check-data.js      # 投入済みデータの整合性
node chiiki/tools/build.js           # 配布物を書き出す（--review で画面だけ）
```

`build.js` は `check-data.js` を先に通し、エラーがあれば中止します。
データが空のときは配布物を作りません（中身のないツールを配ってしまわないため）。
外部から読み込むファイルは作りません（庁内ネットワークで外部サイトが遮断されても、
`file://` で開いても動くようにするため。仕様書 §6）。

### データの取り込み

[`data/source/README.md`](data/source/README.md) に手順があります。おおまかには、

```
位置参照情報（最新年度版・合併前年度版）
  → match-oaza.js  … 代表点を突き合わせ、現在の大字に旧市町村を当てる
  → 中間_大字と旧市町村.csv（人が読める形。手で直せます）
法令別の区域一覧
  → 中間_区域指定.csv・中間_市町村区分.csv
  → build-data.js  → d1/d2 JSON
```

### 設計の要点

- **判定エンジンはデータを持ちません。** 区分・記号・原則の対応はすべて `d3_principles.json` にあり、
  確認表が改訂されたらJSONだけ直せば足ります。
- **旧市町村は座標で当て、名称で検算します。** 仕様書 §4-4 はCODHの旧市町村ポリゴンへの
  点in判定としていますが、位置参照情報を新旧2年度ぶん並べて代表点どうしを対応づける方式にしました。
  点をポリゴンに落とすのではなく点と点を対応づけるため、**仕様書 §7-1 の「大字が旧市町村境を
  またぐ場合の誤判定」が原理的に生じません**。GISライブラリも不要です。
  そのかわり「どの旧市町村か決められない」場合が出るので、正直に「要確認」を返します。
- **合併で大字名の頭に旧市町村名が付くことを織り込んでいます。** 「旧八雲村 日吉」が
  「松江市 八雲町日吉」になるようなパターンで、座標の突合を名称で検算できます。
- **(c) は法令の網羅性を前提にします**（上記「(c) と言い切れる条件」）。
- **転入地が(a)固定であることを前提にしています**（仕様書 §2-2）。そのため確認表のうち
  「3大都市圏外／全部条件不利地域」の1列だけを持ち、記号は ○・△・× の3種しか出ません。
- **人口減少率例外**（2005〜2015年の減少率11%以上）は、3大都市圏内でも圏外として扱います（仕様書 §4-2）。
  `d1` の `人口減少率例外` フラグを立ててください。
- **索引は `Object.defineProperty` で非列挙にしています。** 普通に代入すると `JSON.stringify` で
  複製され、データを直したのに索引だけ古いまま、という不具合が起きます。
- **テストは架空データで行います。** 実在の市町村を使うと、実データの誤りとテストの期待値が
  混ざり、どちらを直せばよいのか分からなくなるためです。

### 仕様書からの変更点（意図的なもの）

- **CODH のポリゴンへの点in判定をやめ、位置参照情報の新旧突合にしました**（上記）。
- **履歴は自動保存にしていません。** 「履歴に残す」を押したときだけ保存します。
  応募者の住所という個人情報を、押していないのに端末へ残さないためです。
- **(c) の判定に法令の網羅性を要求します。** 仕様書の判定フローは (b) でなければ (c) としていますが、
  一覧が揃っていない状態でこれをすると、確かめていないことを確かめたことにしてしまいます。

### この環境の制約（データを持ち込む理由）

外部通信が組織のイーグレスポリシーで絞られており、総務省・国土交通省・CODH のいずれにも
接続できません（`www.soumu.go.jp` / `nlftp.mlit.go.jp` / `geoshape.ex.nii.ac.jp` とも 403）。
通るのは raw.githubusercontent.com / api.github.com / registry.npmjs.org / pypi.org だけです。

そのため原典資料は `data/source/` に置いていただく運用にしています。
将来これらのドメインが許可されれば、`tools/ingest/` はそのまま自動更新に使えます。

なお大字の一覧だけは、位置参照情報を出典とする
[geolonia/japanese-addresses](https://github.com/geolonia/japanese-addresses)（CC BY 4.0）が
GitHub から取得できるため、最新年度版の代わりに使えます。
合併前の年度版はここにはないので、そちらは持ち込みが必要です。
