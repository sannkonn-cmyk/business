# 地域おこし協力隊　地域要件確認ツール

応募者の現住所から、**雲南市への転入が特別交付税措置の対象になるか**を判定し、
出典を明記した根拠テキストを出します。決裁に添える参考資料として使えます。

既存の確認ツールの多くは市町村単位で止まっており、**一部条件不利地域にお住まいの方**
（同じ市町村内でも住所によって結論が変わる）の判定ができません。そこを埋めるためのツールです。

> ### いまは暫定データです
>
> 同梱しているデータは、**出典資料と未照合の手入力の暫定値**です。
> 画面の作りと根拠テキストの書式を確認していただくために仮に入れてあります。
> **この判定結果を決裁資料に用いないでください。**
> 照合のしかたは [`data/照合チェックリスト.md`](data/照合チェックリスト.md) にあります。

---

## 使い方

**`地域要件確認ツール.html`（リポジトリ直下）を開くだけです。** これ1つで動きます。

- ダブルクリックで開く（インストール不要・インターネット接続も不要）
- 庁内共有フォルダに置いても、URLで開いてもかまいません

入力した内容は、**すべてご自分のパソコンの中だけで処理されます。**
外部のサーバーには一切送信されません。

### 画面の見かた

| | |
|---|---|
| 左 | 入力。都道府県 → 市町村 → 大字 の順に選びます |
| 右 | 判定結果と根拠テキスト。選ぶそばから変わります |

### 判定の順序

```
① 住所を選ぶ
② 市町村の区分を見る
     全部条件不利地域(a)              → 対象外
     都市地域                          → 対象
     指定都市（条件不利地域を含まない）→ 対象
     一部条件不利地域                  → ③へ
     指定都市（条件不利地域を含む）    → ③へ
③ 大字の区域を見る
     条件不利区域(b)     → 対象外
     (b)以外＝(c)        → 対象
     境界跨ぎ・未収録    → 要確認
```

②で結論が出る市町村では、**大字の欄は選べないままになります。**
選ぶ必要がないことが画面でわかるようにしてあります。

### 例外ルート

次のいずれかに当てはまる方は、住所にかかわらず対象です。
チェックを入れると住所欄が灰色になり、例外ルートで結論を出します。

- 地域おこし協力隊の経験者（同一地域で2年以上活動し、解嘱から1年以内）
- 海外に在留し、市町村の住民基本台帳に登録されていない
- JETプログラムの終了者（2年以上参加し、終了から1年以内）

### 履歴

**「履歴に残す」を押したときだけ**保存されます。押さなければ、入力した住所は
このパソコンに残りません。保存した履歴はブラウザの中だけにあり、外部には送信されません。

共有の端末をお使いの場合は、使い終わったら履歴画面の**「すべて削除」**を押してください。

### 根拠テキストの出しかた

| | |
|---|---|
| コピー | クリップボードに入れて、決裁文書に貼り付けます |
| 印刷 | 根拠テキストだけを1枚に印刷します。ブラウザのPDF出力でそのまま添付できます |
| .txt で保存 | テキストファイルとして保存します |

> 他のページに埋め込んで表示している場合（レビュー用の共有ページなど）は、
> ブラウザの決まりで **ファイルの保存だけが止められます**。
> コピーと印刷はそのまま使えます。

## この判定の限界

1. **代表点による判定です。** 大字が旧市町村の境をまたぐ場合、誤判定のおそれがあります。該当分は「要確認」を返します。
2. **番地レベルの指定には対応していません。** 区域指定が旧市町村単位であることを前提にしています。
3. **データの鮮度。** 総務省の資料が更新されたら差し替えが必要です。基準日から3年が過ぎると画面に警告が出ます。
4. **収録は島根県のみです。** 島根県外にお住まいの方は判定できません。

本ツールは参考資料を作る補助ツールです。判定の最終責任は使用者にあります。
疑義がある場合は総務省又は島根県へ照会してください。

## 開発者向け

### ファイル構成

```
地域要件確認ツール.html   ← 配布物。ビルド結果（これ1つで動く）
chiiki/
  src/
    app.html    画面の骨組み
    app.css     見た目（同リポジトリの公用文ジェネレーターの配色を踏襲）
    judge.js    判定エンジン（純関数。ブラウザ／Nodeの両方から読める）
    report.js   根拠テキストの組み立て（同上）
    app.js      画面の動き・プルダウン連動・履歴
  data/
    meta.json               基準日・出典・データ状態
    d1_municipalities.json  市町村マスタ
    d2_oaza.json            大字→区域(b/c) テーブル
    d3_principles.json      確認表（区分→記号→原則）
    照合チェックリスト.md   ↓ make-checklist.js が生成
  tools/
    build.js          1つのHTMLにまとめる
    check-data.js     データの整合性検査
    test-judge.js     判定エンジンの単体テスト
    make-checklist.js 照合チェックリストの生成
  dist/
    artifact.html  レビュー用（bodyの中身だけ）
```

### ビルド

```
node chiiki/tools/build.js
```

`check-data.js` を先に通し、エラーがあればビルドを中止します。
外部から読み込むファイルは作りません（庁内ネットワークで外部サイトが遮断されても、
`file://` で開いても動くようにするため。仕様書 §6）。

### 検査

```
node chiiki/tools/check-data.js     # データの整合性
node chiiki/tools/test-judge.js     # 判定エンジンの全分岐
node chiiki/tools/make-checklist.js # 照合チェックリストの作り直し
```

### データを差し替えるとき

**プログラムを直す必要はありません。** `data/*.json` を入れ替えてビルドし直すだけです。

1. `data/*.json` を直す
2. `node chiiki/tools/check-data.js` を通す
3. すべて照合できたら `meta.json` の `dataStatus` を `"verified"` にする
   → 画面の警告バーと、根拠テキスト冒頭の警告が自動的に消えます
4. `node chiiki/tools/build.js`

島根県以外を足す場合も、`d1` に行を、必要なら `d2` に大字を足すだけです。
`d1` の `sample: true` が付いた4件は判定分岐を画面で確かめるための仮データなので、
実データがそろったら削除して差し支えありません。

### 設計の要点

- **判定エンジンはデータを持ちません。** 区分・記号・原則の対応はすべて `d3_principles.json` にあり、
  確認表が改訂されたらJSONだけ直せば足ります。
- **転入地が(a)固定であることを前提にしています**（仕様書 §2-2）。そのため確認表のうち
  「3大都市圏外／全部条件不利地域」の1列だけを持ち、記号は ○・△・× の3種しか出ません。
  転入地を可変にする場合は `d3` を列方向に増やす設計に変えてください。
- **記号△の説明文は (b) と (c) で出し分けます。** 同じ行でも「(c)から転入」と「(b)から転入」で
  文意が変わるため、`説明c` / `説明b` を持たせています。
- **人口減少率例外**（2005〜2015年の減少率11%以上）は、3大都市圏内でも圏外として扱います（仕様書 §4-2）。
  判定エンジンは `d1` の `人口減少率例外` フラグを見る用意ができています。リストが入手でき次第、
  該当団体に `true` を立ててください。
- **索引は `Object.defineProperty` で非列挙にしています。** 普通に代入すると `JSON.stringify` で
  複製され、データを直したのに索引だけ古いまま、という不具合が起きます。

### 仕様書からの変更点（意図的なもの）

- **履歴は自動保存にしていません。** 「履歴に残す」を押したときだけ保存します。
  応募者の住所という個人情報を、押していないのに端末へ残さないためです。
- **動作確認用サンプルの市町村を4件同梱しています。** 島根県には都市地域・指定都市がなく、
  そのままでは判定分岐の半分を画面で確かめられないためです。`sample: true` で区別し、
  都道府県のプルダウンでも「（動作確認用サンプル）」として実データと分けています。
- **データの照合状態を判定結果に持ち上げています。** 未照合の市町村・原則を使った判定には、
  画面と根拠テキストの双方にその旨が出ます。暫定データのまま決裁に回ることを防ぐためです。

### この環境で実行できなかったこと

仕様書 §4-4 のGIS前処理（位置参照情報の代表点をCODHの旧市町村ポリゴンに点in判定する）は、
外部通信が遮断された環境のため実行できていません。総務省・国土交通省・CODH のいずれにも
接続できず（proxy が 403 を返す）、出典資料そのものを取得できませんでした。

そのため `d2_oaza.json` は手入力の暫定値です。ネットワークのつながる環境で
[`data/照合チェックリスト.md`](data/照合チェックリスト.md) に沿って進めてください。
