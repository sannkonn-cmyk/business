# 原典資料の置き場所

このフォルダに原典資料を置き、取り込みツールで `chiiki/data/*.json` を作ります。
**JSON を手で書くことはありません。** 原典は出典を示すためリポジトリに含めます。

---

## いま入っているもの

| ファイル | 中身 | 何が決まるか |
|---|---|---|
| `地域要件確認表.pdf` | 総務省。令和4年4月1日現在 | **全国1,741団体の地域要件区分**（都市地域／全部条件不利／一部条件不利）、3大都市圏、指定都市、人口減少率例外 |
| `過疎地域市町村等一覧_R4.4.1.pdf` | 総務省。令和4年4月1日現在 | 一部過疎158団体の**条件不利区域にあたる旧市町村名** |
| `位置参照情報_大字町丁目_R7_全国.zip` | 国土交通省。令和7年度版・全47都道府県 | 全国191,106件の**大字・町丁目と代表点** |

この3つで、**判定フローのステップ②（市町村の区分）は全国で完成しています。**
1,741団体のうち 819が「住所によらず対象外」、630が「住所によらず対象」と確定します。

## まだ足りないもの

残るのは**ステップ③（一部条件不利地域292団体の区域 b/c）**だけです。

### 島根県を仕上げるのに要るもの

島根県で区域判定が必要なのは**松江市と出雲市の2団体だけ**です。しかも過疎の区域
（松江市＝旧鹿島町・旧島根町・旧美保関町、出雲市＝旧佐田町・旧多伎町）は
大字名の接頭辞で解けているので、**A17 過疎地域は要りません。**

| 要るもの | 国土数値情報 | 島根県のフォルダだけで十分 |
|---|---|---|
| 振興山村 | **A24** | `A24-*_32_*` |
| 離島振興対策実施地域 | **A19** | `A19-*_32_*` |
| 半島振興対策実施地域 | **A18** | `A18-*_32_*` |

**全国版をまるごとではなく、`32`（島根県）のフォルダだけを取り出して置いてください。**
GeoJSON でお願いします。

> ### 渡し方と大きさの上限
>
> | 経路 | 上限 |
> |---|---|
> | チャットに添付 | 数MB程度（3.1MBの位置参照情報zipは通りました） |
> | Google Drive | **1ファイル10MBまで**（それを超えると取り出せません） |
> | drive.google.com への直接アクセス | 不可（ネットワークポリシーで遮断） |
>
> 全国版は A17 が212MB、A24が98MB、A18が69MB、A19が24MB あり、どの経路にも収まりません。
> 都道府県ごとに分ければ1つ数MBに収まるはずです。

### 他県に広げるとき

区域判定が必要な292団体は43都道府県にまたがります（長野17・福島14・福岡12・新潟11…）。
使う見込みのある県から順に足していけば足ります。`ポリゴン設定.json` の `ファイル` は
配列で書けるので、県を足すたびに1行足すだけです。あわせて `収録県` に県コードを
足してください（収録外の県の大字を「どのポリゴンにも入らない＝(c)」と決めつけないためです）。

なお A17 過疎地域は、大字名から旧市町村を特定できなかった74団体を補うために使います。
島根県には該当がないので、他県に広げるときに必要になります。

## 取り込みの順序

```
① python3 chiiki/tools/ingest/read_kakuninhyou_pdf.py
     地域要件確認表.pdf → 中間_市町村区分.csv（全国1,741団体）

② python3 chiiki/tools/ingest/read_kaso_pdf.py
     過疎地域市町村等一覧.pdf → 中間_過疎一覧.csv（885団体・区域347件）

③ node chiiki/tools/ingest/match-by-prefix.js
     大字名の接頭辞から旧市町村を当てる → 中間_大字と区域.csv
     （158団体中84団体が解け、74団体はポリゴン待ちとして要確認になります）

④ node chiiki/tools/ingest/add-polygon-laws.js [県コード]     ※ポリゴンが要ります
     山村・離島・半島の b/c を埋め、過疎の未解決分を補う

⑤ node chiiki/tools/ingest/build-data.js
     中間CSV → d1_municipalities.json / d2_oaza.json

⑥ node chiiki/tools/check-data.js
   node chiiki/tools/ingest/report-coverage.js
   node chiiki/tools/build.js
```

①②は Python（`pip install pypdf`）を使います。本体は Node だけで動きます。
**中間CSVをリポジトリに残してあるので、pypdf が無い環境でも③以降は流せます。**

> この環境では、システムの `cryptography` が壊れていて pypdf が読み込めません。
> 暗号化されていないPDFなので、次のように迂回してください。
> ```
> mkdir -p /tmp/stub && echo 'raise ImportError' > /tmp/stub/cryptography.py
> PYTHONPATH=/tmp/stub python3 chiiki/tools/ingest/read_kakuninhyou_pdf.py
> ```

## ファイルの形

### `取得記録.json`

いつ・どこから落としたかと、**どの法令の区域一覧を投入したか**を残します。
`資料` は根拠テキストの出典欄に出ます。

```json
{
  "基準日": "令和4年4月1日",
  "収録法令": ["過疎"],
  "資料": [{ "名称": "…", "url": "…", "現在日": "令和4年4月1日", "取得日": "2026-08-23" }]
}
```

`収録法令` がこの仕組みの要です。ここに書いた法令だけが各市町村の `照合済み法令` に立ちます。
条件不利区域(b) は4法令の和集合なので、

- **(b) だと言うには**、1つ載っていれば足ります
- **(c) だと言うには**、4つのどれにも載っていないことを確かめる必要があります

したがって、**投入していない法令を `収録法令` に書くと、確かめていないことを確かめたことに
してしまいます。** 実際に投入した法令だけを書いてください。

### `ポリゴン設定.json`

```json
{
  "緩衝m": 300,
  "収録県": ["32"],
  "法令": {
    "山村": { "ファイル": ["A24_32.geojson"], "区域名の属性": ["旧市町村", "名称"] },
    "離島": { "ファイル": ["A19_32.geojson"], "区域名の属性": ["島名", "名称"] },
    "半島": { "ファイル": ["A18_32.geojson"], "区域名の属性": ["地域名", "名称"] },
    "過疎": { "ファイル": [], "旧市町村名の属性": ["旧市町村"] }
  }
}
```

`ファイル` は配列で、県を足すたびに増やせます。`収録県` に県コードを並べると、
そこだけを判定し、収録外の県の大字はポリゴン未判定のまま（＝要確認）に保ちます。

属性の名前はデータセットごとに違います。落としたら
`node chiiki/tools/ingest/read-geojson.js <ファイル>` で属性の一覧を出し、
それを見て書いてください。

`緩衝m` は境界の緩衝帯です。代表点がポリゴンの境界からこの距離より近いと、
内外にかかわらず「要確認」を返します（仕様書 §7-1 の誤判定対策）。

### 中間CSV

取り込みの途中を人が読める形で止めるためのものです。ツールが作りますが、手で直しても構いません
（直したら ⑤ から流し直してください）。

| ファイル | 作るもの |
|---|---|
| `中間_市町村区分.csv` | ① 地域要件確認表から |
| `中間_過疎一覧.csv` | ② 過疎地域市町村等一覧から |
| `中間_大字と区域.csv` | ③④ 大字1件ごとの法令別 b/c |
| `中間_接頭辞照合の結果.csv` | ③ どの旧市町村が解けたか（目で確かめる用） |
| `中間_指定一覧.csv` | 山村・離島・半島を**一覧**で持つ場合に手で作る |

`中間_指定一覧.csv` の形:

```
都道府県名,市町村名,法令,指定区分,区域,出典,基準日
島根県,松江市,半島,一部,鹿島町|島根町,半島振興対策実施地域一覧,令和4年4月1日
```

## 原典なしで仕組みを確かめる

```
node chiiki/tools/test-ingest.js     # 接頭辞照合・点in判定・市町村区分（合成データ）
node chiiki/tools/test-pipeline.js   # 中間CSV → JSON → 判定 の通し（合成データ）
```

実データで思ったとおりに動かないときは、まずこの2つを流して、
取り込みの仕組み自体が壊れていないかを確かめてください。
