# 公用文ジェネレーター

平易な通知文（公用文）の**レイアウト調整の手間をなくす**ツールです。
画面に必要事項を入れてボタンを押すと、体裁の整った **Wordファイル** が出てきます。
本文は、出てきたWordファイルにあとから書き込みます。

---

## 使い方

**`公用文ジェネレーター.html` を開くだけです。** これ1つで動きます。

- ダブルクリックで開く（インストール不要・インターネット接続も不要）
- 社内サイトやGitHub Pagesなどに置いて、URLで開いてもかまいません

入力した内容は、**すべてご自分のパソコンの中だけで処理されます。**
外部のサーバーには一切送信されません。

> **ご注意：** 他のページの中に埋め込んで表示している場合（プレビュー用の共有ページなど）は、
> ブラウザの安全上の決まりで **Wordファイルのダウンロードだけが止められます**。
> 見た目と項目の確認はそのままできますが、実際に文書を作るときは
> `公用文ジェネレーター.html` をパソコンに保存し、ダブルクリックで開いてください。
> （埋め込み表示のときは、画面上部にその旨のお知らせが出ます）

### 画面の見かた

| | |
|---|---|
| 左 | 入力フォーム。**すべての項目が任意**です。空欄の項目はWordに出力されません（空行も残りません） |
| 右 | できあがりイメージ。入力しながら結果が見えます |

### 覚えさせておける項目

何度も同じ内容を打たなくて済むように、次の2つを登録できます。
登録した内容は**ブラウザを閉じても消えません**。「管理」ボタンから並べ替え・削除ができます。

- **文書記号**（例：商工労）
- **発信者セット**（発信者1行目・2行目＋連絡先をひとまとめ）

パソコンを入れ替えるときや同僚に配るときは、画面右上の
**「設定の書き出し・読み込み」** からファイルに書き出してください。

### 様式が変わったら

画面右上の **「ひな形の確認・差し替え」** から、新しいWordのひな形（.docx）を読み込ませてください。
用紙サイズ・余白・フォント・行送りは、読み込ませたひな形のものがそのまま使われます。
**プログラムを直す必要はありません。**

## 自動でやってくれること

| | |
|---|---|
| 元年表記 | 年に「1」を入れると `令和元年` と出ます |
| 文書番号の整形 | 記号「商工労」＋番号「123」→ `商工労第123号`。「号外」を選ぶと `商工労号外`（「第○号」は付きません） |
| 年度の判定 | 「4月1日」＝今年度の4月1日／「3月31日」＝今年度末 |
| 空欄の扱い | 入力がない項目は行ごと出力しません |
| 日付の空欄 | 年・月・日のうち空欄にしたところは、あとから書き込めるよう**空白のまま**出力します（例：`令和8年8月　日`）。3つとも空欄なら日付の行ごと出しません |
| 均等割り付け | あて先／発信者名／文書番号・日付を、それぞれ一番長い行の幅にそろえます |
| 波括弧 | あて先が2件以上なら自動で `}` でまとめ、敬称を1つだけ**上下中央**に置きます |
| 公印枠 | 「公印を押す」を選ぶと、氏名の最後の文字に半分かかる位置に28mm角の赤枠を出します |
| 1ページに収める | あて先や表題が長いときは、本文の空き行数を自動で減らして1ページに収めます |
| ファイル名 | `YYYYMMDD_表題.docx`（表題が空欄なら `YYYYMMDD_公用文.docx`） |

### あて先が偶数行でも敬称が中央に来ます

ひな形のコメントでご指摘のあった点です。
あて先を**罫線なしの表**で組み、敬称のセルを「上下中央そろえ」にすることで解決しています。

## 決めごと（仕様書の未確定事項への対応）

| # | 内容 | 決定 |
|---|---|---|
| 1 | 本文エリアの空き行数 | 画面での指定はなし。**1ページに収まるよう自動で決めます**（下限3行） |
| 2 | 連絡先ボックスの位置 | **ひな形どおり段落基準**。本文を書き足すと下へ動きます |
| 3 | 「事務連絡」のときの発信者名 | **何も変えません**。入力欄を空にすれば出ません |
| 4 | 出力の保存先 | ブラウザのダウンロードフォルダ |

そのほか、「末尾に『以上』を入れる」は実務上使わないため、機能ごと外しています。

## 開発者向け

### ファイル構成

```
公用文ジェネレーター.html   ← 配布物。ビルド結果（これ1つで動く）
src/
  app.html    画面の骨組み
  app.css     見た目（UIモックv3を踏襲）
  app.js      画面の動き・登録機能・プレビュー
  docx.js     Word（.docx）の組み立て
template/
  例文.docx   ひな形（同梱。base64でHTMLに埋め込まれる）
vendor/
  jszip.min.js  JSZip 3.10.1（MIT）
tools/
  build.js    上記を1つのHTMLにまとめる
dist/
  artifact.html  レビュー用（bodyの中身だけ）
```

### ビルド

```
node tools/build.js
```

`src/` `vendor/` `template/` を読み、`公用文ジェネレーター.html` を書き出します。
外部から読み込むファイルは作りません（庁内ネットワークで外部サイトが遮断されても動くようにするため）。

### 出力のしくみ

1. 埋め込んだ `例文.docx`（base64）をJSZipで展開
2. `word/document.xml` の `<w:body>` 〜 `<w:sectPr>` の**間だけ**を、入力値から組み立てたXMLで差し替え
3. `<w:sectPr>`（用紙・余白・行送り）と `styles.xml` / `theme1.xml` / `fontTable.xml` は**一切触らない**
4. ひな形に残っているレビューコメント（`comments.xml` ほか）を関連部品ごと削除
5. ZIPに固め直してダウンロード

### 仕様書からの変更点（意図的なもの）

- **均等割り付けは `w:fitText` ではなく `w:jc="distribute"` を使用。**
  段落の使える幅をそろえたい幅ちょうどに絞り、その中で文字を散らします。
  `fitText` はWord以外のソフト（LibreOffice、Googleドキュメント等）で無視されて
  ずれて見えるため、より素直に伝わる方式にしました。ひな形自身も同じ方式です。
  折り返しを防ぐため、基準幅は文字単位に切り上げ、半角を含む行には全角1文字ぶん余裕を足しています。
- **波括弧は浮動図形（`wp:anchor`）として配置。**
  インライン図形だと行の高さに引っぱられて上へずれるためです。
- **テキストボックス内の段落に `w:spacing w:line="240" w:lineRule="auto"` を明示。**
  ひな形の既定が `w:line="60"`（行送り25%）で、行グリッドの効かない
  テキストボックスの中では行が重なってしまうためです。

### 動作確認

`公用文ジェネレーター.html` をブラウザで開き、出力した .docx を Word で開いてください。
連名3件／連名2件（偶数行）／1件／最小構成／長いあて先6件／極端に長い1行の6パターンで、
XMLの妥当性・1ページに収まること・図形の位置を確認済みです。
